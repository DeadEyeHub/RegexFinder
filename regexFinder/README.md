# regexFinder

`regexFinder` — программа для Windows, которая читает текстовые выгрузки кассовых аппаратов, находит в них данные и сохраняет результат в CSV.

Программа работает по YAML-файлу с правилами поиска. В YAML описано, где находятся номер чека, сумма, товары, оплата, hash-значения и другие поля.

## Что Нужно Для Работы

Нужны два файла:

1. Исходный текстовый файл с чеками, например `merged.txt`.
2. YAML-файл с правилами, например `blueprint.yaml`.

После обработки программа создаёт третий файл:

3. CSV-файл с результатами.

Пример исходной строки:

```text
N N Šasijas Nr:PMN010320 SD2 000173
```

Из неё программа может получить:

```text
Sasijas numurs = PMN010320
Ceka numurs = 000173
```

## Запуск

Запустите файл `regexFinder.exe`.

После запуска появится главное окно. Внизу окна показываются версия программы и время сборки.

## Основной Порядок Работы

### Шаг 1. Загрузить TXT

Нажмите:

```text
Upload cash register bills
```

Выберите исходный TXT-файл с чеками.

Программа показывает имя файла и количество загруженных строк.

По умолчанию включён UTF-8. Если файл старый и содержит латышские символы, программа пытается автоматически перейти на Windows-1257. Если символы всё равно отображаются неправильно, попробуйте загрузить файл ещё раз с подходящей кодировкой.

### Шаг 2. Загрузить YAML

Нажмите:

```text
Upload Regex commands
```

Выберите YAML-файл.

В нём обязательно должен быть паттерн с именем `Splitter`. Он сообщает программе, где начинается новый чек.

После загрузки программа показывает количество найденных паттернов.

### Шаг 3. Создать CSV

Нажмите:

```text
Transform
```

После обработки выберите папку и имя CSV-файла.

Программа сохраняет все поля в том порядке, в котором они находятся в YAML.

CSV сохраняется с корректным экранированием кавычек и запятых, поэтому его можно открывать в Excel.

## Главное Правило О Полях

Каждый элемент в `patterns` описывает одну колонку CSV.

Пример:

```yaml
- name: Summa
  regexCommand: '...'
  valueType: decimal
  combineMethod: first
```

Значения:

- `name` — название колонки в CSV.
- `regexCommand` — регулярное выражение для поиска.
- `valueType` — тип значения: `string`, `integer`, `decimal`, `date`, `time`.
- `combineMethod` — что делать, если найдено несколько значений.
- `blockName` — искать паттерн только внутри блока с этим именем.
- `multiline` — искать по нескольким строкам.
- `linesCount` — сколько строк объединять при `multiline`.

## Блоки Внутри Чека

После разделения файла по `Splitter` программа может разделить каждый чек на несколько блоков. Блоки задаются в секции `blocks`, а паттерн связывается ровно с одним блоком через `blockName`:

```yaml
blocks:
  - name: items
    startsWith: '^N B ITEM'
    endsWith: '^N B END ITEM'

patterns:
  - name: Items total
    blockName: items
    regexCommand: '^N B ITEM.*?([0-9]+[.,][0-9]+)'
    valueType: decimal
    combineMethod: sum
```

Один и тот же блок может повторяться несколько раз внутри чека. Все найденные значения паттерна из этих блоков объединяются согласно `combineMethod`. Паттерны без `blockName` ищутся по всему чеку.

Мультистрочные паттерны обрабатываются только внутри своего диапазона блока и не могут захватить строки соседнего блока. Если конец блока не найден, он временно закрывается на последней строке текущего чека, чтобы повреждённый чек не остановил всю обработку.

## Способы Объединения Значений

### `first`

Взять первое найденное значение.

Подходит для:

- номера чека;
- даты;
- времени;
- номера кассы;
- hash-значений.

### `sum`

Сложить все найденные значения.

Пример:

```text
Alkohols 10.00
Alkohols 6.00
```

Результат:

16.00
```

### `merge`

Объединить несколько текстовых значений.

### `last`

Взять последнее найденное значение. Этот режим используется для `Summa`, когда внутри одного чека есть промежуточные строки `SUMMA`, а финальная сумма находится в последней строке `KOPĀ SUMMA`.

## Отрицательные Корректировки

Некоторые чеки сначала содержат товар, а потом его аннулируют:

```text
Alkohols 40.00
Alkohols -40.00
Alkohols 4.00
```

Правильный результат:

```text
4.00
```

Для такого поведения в YAML указывается:

```yaml
applyNegativeAdjustments: true
```

Если поле не содержит этого свойства, используется:

```text
false
```

Отрицательное значение сохраняет свой знак и уменьшает итоговую сумму.

После числа могут находиться дополнительные символы кассового формата:

```text
40.00A
8.50B
```

Паттерн должен брать число и не ломаться из-за суффикса.

## Важные Поля В Текущем YAML

В `blueprint.yaml` настроены поля:

- `Nosakums` — название организации.
- `J/ad.` — адрес.
- `VRN` — регистрационный номер.
- `Sasijas numurs` — номер кассы или шасси.
- `Ceka tips` — тип чека.
- `Ceka numurs` — номер чека.
- `Date` — дата.
- `Time` — время.
- `Summa` — итоговая сумма чека.
- `Grand total` — отдельное поле, если такой текст есть в исходнике.
- `Pardosanas ceks` — сумма продаж.
- `Bez pvn` — сумма без PVN.
- `PVN` — налоговая сумма.
- `Ēdieni` — еда.
- `Dzērieni` — напитки.
- `Alkohols` — алкоголь.
- `Skaidra nauda` — наличные.
- `Izdots` — выдано.
- `Bankas karte` — банковская карта.
- `Anulets` — аннулированная сумма.
- `Ielikta nauda` — внесённые деньги.
- `Iznemta nauda` — изъятые деньги.
- `s`, `S`, `Z`, `H` — hash-значения.

## Окно CSV Validation Tests

Кнопка `Tests` открывает отдельное окно проверки CSV.

Тесты работают непосредственно с выбранным CSV. Они не пересчитывают TXT и не сравнивают его с новым результатом обработки.

### Поля В Окне Тестов

- `CSV to check` — CSV-файл для проверки.
- `Test name` — название пользовательской проверки.
- `Test type` — тип проверки.
- `Run checks` — запустить проверки.
- `Add check` — добавить правило.
- `Delete check` — удалить выбранное правило.
- `Save checks` — сохранить правила в YAML.
- `Load checks` — загрузить правила из YAML.
- `Export failures` — экспортировать ошибки.
- `Inject corrected CSV` — заменить исправленные строки в общем CSV.

## Типы Проверок

### Required field

Проверяет, что выбранная колонка не пустая.

Пример:

```text
Field: Ceka numurs
```

### Compare fields

Проверяет формулу между колонками.

Пример:

```text
Summa = Ēdieni + Dzērieni + Alkohols - Anulets
```

Порядок настройки:

1. Выберите `Compare fields`.
2. В `Field to compare` выберите `Summa`.
3. В списке доступных колонок отметьте нужные поля.
4. Нажмите `+ Add field`, чтобы прибавить их.
5. Отметьте поле и нажмите `- Remove field`, чтобы вычесть его.
6. Проверьте список `Formula terms`.
7. Укажите допуск в `Tolerance`.
8. Нажмите `Add check`.

Если формула проходит, пустые необязательные поля не считаются ошибкой.

Если формула не проходит, программа показывает конкретные пустые поля.

Если все поля формулы пустые, отображается:

```text
All fields empty.
```

Можно отметить `Ignore receipt types`, чтобы не проверять некоторые типы чеков.

### Hash chain

Проверяет связь hash-значений между строками.

Обычно используется:

```text
Previous hash field: S
Current hash field: s
Order by: Ceka numurs
```

Проверяется:

```text
previous.S == current.s
```

### Number sequence

Проверяет последовательность номеров.

Пример:

```text
Field: Ceka numurs
Order by: Ceka numurs
Sequence step: 1
```

Проверяется:

```text
текущее значение = предыдущее значение + шаг
```

### Grand total check

В CSV может не быть отдельной колонки `Grand total`. В таком случае одна и та же колонка `Summa` имеет разный смысл в зависимости от типа чека:

- у обычного `ČEKS` это сумма операции;
- у `X Pārskats` или `Dienas Z Pārskats` это контрольный Grand Total.

Настройка:

1. Выберите `Grand total check`.
2. В `Amount / grand total field` выберите `Summa`.
3. В `Receipt type field` выберите `Ceka tips`.
4. В `Transaction receipt types` отметьте обычные чеки, например `ČEKS`.
5. В `Checkpoint receipt types` отметьте отчётные типы, например `X Pārskats` и `Dienas Z Pārskats`.
6. В `Exclude when nonzero` выберите `Anulets`.
7. Укажите допуск.
8. Добавьте проверку.

Алгоритм:

1. Найти первый выбранный контрольный тип.
2. Взять чеки после предыдущего отчёта и до него.
3. Оставить только выбранные обычные типы чеков.
4. Исключить чеки с ненулевым `Anulets`.
5. Сложить их `Summa`.
6. Взять `Summa` из текущей контрольной строки.
7. Прибавить текущий диапазон к накопленной сумме предыдущих диапазонов.
8. Сравнить накопленную сумму с `Summa` контрольной строки.
9. Повторить проверку для следующего отчёта.

## Экспорт Ошибок

После запуска проверок нажмите `Export failures`.

Выберите папку. Для каждой проверки с ошибками появятся два файла:

```text
<название проверки>.csv
<название проверки>.txt
```

CSV содержит только строки, связанные с ошибкой.

TXT содержит оригинальные блоки чеков по ключу `Ceka numurs`.

Для ошибки `Grand total check` в TXT попадает весь диапазон, который участвовал в расчёте ошибочного отчёта.

Если исходный TXT не был загружен в главное окно, программа не сможет восстановить блоки и покажет сообщение вместо создания пустого файла.

## Исправление И Инъекция CSV

После ручного исправления ошибочного CSV нажмите `Inject corrected CSV`.

Выберите:

1. Основной CSV в поле `CSV to check`.
2. Исправленный CSV.
3. Имя нового файла.

Строки заменяются по колонке `Ceka numurs`. Основной файл не изменяется.

Перед заменой проверяются:

- наличие `Ceka numurs`;
- отсутствие пустых ключей;
- отсутствие дубликатов ключей;
- наличие ключей в основном CSV;
- совпадение заголовков.

## Если Результат Неправильный

### Все латышские символы отображаются неправильно

Проверьте кодировку исходного TXT. Программа поддерживает UTF-8 и Windows-1257.

### Колонка пустая

Проверьте:

- правильный ли выбран YAML;
- правильная ли кодировка TXT;
- совпадает ли текст строки с `regexCommand`;
- нет ли суффикса после числа;
- загружен ли нужный тип чека.

### Сумма слишком большая

Проверьте:

- не включены ли отчётные чеки в обычные транзакции;
- не учитываются ли аннулированные чеки;
- включён ли `applyNegativeAdjustments` для нужного поля;
- не складываются ли промежуточная и финальная суммы одновременно.

### TXT с ошибками пустой

Загрузите исходный TXT в главном окне до открытия `Tests`. Для поиска оригинальных блоков нужен ключ `Ceka numurs`.
